PLAY 01

一句话，把 OpenClaw 讲成会动的网页

真正的新意不是“儿童化语气”，而是把回答的默认介质从文字换成网页。它天然适合每日样刊，也能成为自媒体母版。

怎么试

  1. 选一个你已经听过、但一直没真正弄懂的 AI 概念。
  2. 把下方 Prompt 交给能创建文件的 Codex、Claude Code 或其他 Agent。
  3. 要求输出单文件 HTML，直接在手机尺寸浏览器打开。
  4. 删掉任何需要第二遍阅读的句子；若一屏超过一个概念，让 Agent 重做。

可复制指令

请把我当成完全不懂这个话题的人，用一个包含大图、少量文字的单文件 HTML 页面解释：OpenClaw 如何从聊天变成会定时做事的个人 AI 助手。手机优先，3 屏内讲完，每屏只讲一个概念；用原创 CSS/SVG 图形，不依赖外部素材；加入一个能亲手操作的小交互，并确保离线打开可用。

别忽略这些

  • 官方 Skill 本质上非常短，效果主要取决于模型的前端与视觉能力，不是安装后就必然变好。
  • 大图少字适合建立直觉，不适合承载完整技术边界；需要保留“查看原理/来源”入口。
  • 若直接发布模型生成页面，常会出现模板化审美、移动端溢出或信息过度简化，仍需人工验收。

PLAY 02

别让最贵的模型搬砖：让它当总导演

它把 Prompt 从“怎么让模型回答更好”推进到“怎么设计一支 AI 团队”。对复杂任务，玩法不再是写神句，而是配置责任边界。

怎么试

  1. 挑一个至少有两个可独立工作流、且最终结果能测试的任务；小任务不要硬拆。
  2. 把下方 Prompt 放在任务开头，并要求主 Agent 给出每个子任务的明确交付物。
  3. 执行时观察主 Agent 是否真的把实现工作派出，而不是只口头说会委派。
  4. 最后检查它有没有亲自读回产物、跑统一测试、处理子 Agent 之间的矛盾。
  5. 用同类小任务做一次不开委派的对照，比较总耗时、失败率和主上下文占用；不要只看感觉。

可复制指令

你的职责是总导演：先澄清目标，并拆成可并行、可验收的任务；把大量代码阅读、具体实现、测试和批量修改交给合适的 subagent。你保留架构判断、任务分发、交叉核验与最终验收。只有当任务很小、委派开销明显更大时才自己完成。持续推进，直到主目标通过真实验证；不要把子 Agent 的完成回执当作验证结果。

别忽略这些

  • 只有支持子 Agent/多 Agent 的产品才能完整复现；普通聊天模型只能模拟任务拆分。
  • 委派有固定开销，单文件小改、一步查询和强耦合任务通常自己做更快。
  • 子 Agent 共享信息不足时会各自做出合理但互相冲突的方案，主 Agent 必须重新验收。
  • 原帖对成本的判断是个体经验；不同模型、计费和上下文缓存下结论可能相反。

编辑推演

给公开报告增加一张“幕后任务树”折叠卡：显示今天由哪些 Agent 找线索、谁核验、谁渲染、谁复测，让读者看到 AI 团队如何协作；只展示角色和动作，不暴露私有路径、群聊或系统信息。

PLAY 03

做完一次，就让 Agent 永久学会

早期 OpenClaw 的惊喜是“AI 能长期住在你的系统里”；Hermes 把下一步做得很直白：它不只记得事实，还能把经历变成操作方法。

怎么试

  1. 只在隔离环境或已有 Hermes 安装中测试，不要为了试玩直接改动现有个人 AI 主环境。
  2. 先和 Agent 完成一段有明确成功标准的真实工作流，并保留失败与修正过程。
  3. 在同一会话输入 `/learn how I just completed this workflow`，补充你希望它下次何时触发。
  4. 用 `/skills` 检查生成项，再让一个新会话仅凭该 Skill 重做一次简化任务。
  5. 对照原过程检查是否漏掉权限、人工确认和验证步骤；有遗漏就更新 Skill 后再测。

可复制指令

/learn how I just completed the daily AI-play report: find public candidates, return to primary sources, separate verified facts from editor inference, structure the winners as story JSON, render the mobile page, run functional and visual QA, and require human approval before posting to external social accounts. Capture triggers, procedure, pitfalls, privacy rules, and verification—not private content or credentials.

别忽略这些

  • “生成了 Skill”不等于“学对了”；必须在新会话用新样本复测，才能判断是否可复用。
  • 对话里若混有一次性的路径、密钥、私人群聊或错误捷径，自动提炼可能把坏习惯永久化。
  • 官方仓库对自我改进的描述包含产品主张；本条只采用文档可核验的 `/learn` 行为，不替它证明长期效果。
  • 现有系统若已有长期记忆与 Skill 体系，直接迁移或并装 Hermes 可能制造两套事实源。

编辑推演

每次成功生成报告后只记录匿名化流程差异；同一步骤稳定成功 3 次，再出现一张“要把这个方法教给 Agent 吗？”卡片。由用户确认后才写 Skill，并自动安排一次新会话回归测试。
